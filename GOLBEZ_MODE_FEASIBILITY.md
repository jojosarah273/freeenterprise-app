# Feasibility — custom playable Golbez as a second engine

**Status: assessed and tested. No code changed.** This records what the
`DEV/FE_GOLBEZ` fork is, how it would be integrated, and the results of the
offset tests that were run to prove the sprite pipeline works.

> **Decision taken:** ship **two distinct engines**, selected at launch — the
> vanilla engine (upstream-updatable from the galeswift git) and this Golbez
> engine. The Golbez engine's scope should be **trimmed** (§8), because removing
> FuSoYa invalidates a large amount of the flag surface.

---

## 1. What the Golbez build is

A fork of **Free Enterprise 4.6.0.open** (`FORK = "open"`) that **replaces FuSoYa
with a hand-made playable Golbez**. The base is confirmed: its README matches
`HungryTenor/FreeEnterprise4` verbatim, and diffing against that repo isolates the
Golbez work cleanly.

### 2.4 Graphics — the real work

Three IPS patches, authored by reverse-engineering where the character data lives:

| Patch | Records | Base ROM region (`<0x100000`) | Expanded region (`≥0x100000`) |
|---|---|---|---|
| `Golbez.ips` | 61 | 16 recs / 712 B — battle block at **`0x0D7600`** | 45 recs / 1574 B at **`0x1D0000`+** |
| `Golbez_Map.ips` | 29 | 27 recs / 523 B — map block `0x0DCF80`, pointer `0x0680EC`, ~22 × 1-byte palette edits at `0x0DDD**` | 2 recs / 771 B — pointer `0x10CB0C`, map GFX at **`0x1D0900`** |
| `Golbez_Portrait.ips` | 2 | 1 rec / 14 B — pointer **`0x0687C0`** | 1 rec / 382 B — portrait at **`0x1D0C02`** |

The pattern: **new artwork is written into free space at `0x1D0000`+ and the
game's pointer tables are repointed at it**, while some original base-ROM blocks
are overwritten. The tiny 4- and 14-byte edits are the pointer updates.

**No `FreeEnt/scripts/` (`.f4c`) files were modified.** The two `f4c` diffs are
`dump.*` data files. The only asset change is `custom_weapons.csvdb` (Golbez's
weapons).

## 3. Offset tests — the sprite pipeline is version-independent ✅

An IPS applier was written and the three patches were applied to ROMs generated by
**our 4.7.0.Gale engine**, then compared against the fork's own patched build
(`golbez_final_test.sfc`).

| Region | Address (size) | Match |
|---|---|---|
| battle block | `0x0D7600` (0x800) | ✅ |
| map block | `0x0DCF80` (0x400) | ✅ |
| pointer table | `0x0680EC` (4 B) | ✅ |
| pointer table | `0x0687C0` (14 B) | ✅ |
| pointer table | `0x10CB0C` (4 B) | ✅ |
| palettes | `0x0DDD00` (0x80) | ✅ |
| new battle data | `0x1D0000` (0x800) | ✅ |
| new map data | `0x1D0900` (0x300) | ✅ |
| portrait | `0x1D0C02` (0x17E) | ✅ |

**9/9 byte-identical, across 5 different flagsets.** The sprites land identically
on a 4.7.0 ROM.

### 3.1 The sprite space is free, and the tables are untouched

`0x1D0000`–`0x1D2000` was `0xFF` in unpatched output for **six** flagsets, and the
portrait pointer table at `0x0687C0` was byte-identical to the base ROM in all six:

```
Cvanilla · Crelaxed · Conly:cecil,rosa,edge · Ctreasure:free
Cstart:cecil Cno:fusoya · wacky:whatsmygear Crelaxed
   → free space True in all six ; pointer table == base ROM in all six
```

So the randomizer never writes into the region the sprites occupy, and never
touches the tables the IPS edits. Combined with `f4c` stripping a 512-byte header
and output always being unheadered `0x200000` (verified), the IPS offsets are
stable regardless of engine version **or** whether the user's base ROM had a
header.

## 4. Two problems the tests exposed

### 4.1 The portrait-mirror step does nothing

`generator.py` copies 382 bytes from `0x1D0C02` to `0x1D0C02 + 382` (`0x1D0D80`)
to give "FuSoYa's slot" Golbez's portrait. But in the fork's **own** patched build
(`golbez_final_test.sfc`), `0x1D0D80` is **all `0xFF`** — nothing was written.
Applying the mirror actually *breaks* the match with the working build.

That is a strong candidate for the unresolved blocker ("actor `0x13` renders
FuSoYa"): the address assumed to be FuSoYa's portrait is not somewhere the game
reads one from, so writing pixels there changes nothing. The fix is likely to
**repoint FuSoYa's table entry** (as the portrait IPS already does for the other
character) rather than copy pixels to a slot address.

### 4.2 The patch step fails silently

The fork's own artifacts split into two groups:

| Patched (`0x0D7600 = 06000900`) | Unpatched (= stock `01000701`) |
|---|---|
| `golbez_final_test`, `golbez_fusoya_final`, `golbez_fusoya_test`, `golbez_fusoyaslot_seed`, `golbez_lunar_palace`, `golbez_test_seed` | `golbez_seed`, `_v2`, `_v3`, `_v4`, `golbez_hero_seed` |

The unpatched group matches stock FE output exactly — they were built **without the
IPS being applied**, because `apply_ips_patch()` begins with:

```python
if not os.path.exists(ips_path):
    return rom_bytes          # ← silent no-op
```

Running from a different working directory makes the `root_dir` lookup miss and the
patches vanish with no warning. **When vendoring, this must become a hard error.**

## 5. No overlap with the vanilla engine's Golbez

4.7.0.Gale ships a `golbez_rando.py`, which invites confusion. It is a different
feature:

| | Vanilla engine (4.7.0.Gale) | This fork |
|---|---|---|
| What | **Boss** Golbez | **Playable** Golbez |
| Module | `golbez_rando.py` (85 lines) | rewrites `fusoya_rando.py` |
| Purpose | randomize the boss's commands/spells | replace FuSoYa as a party member |
| Flags | `Bwhybez`, `Bwhichbez`, `-wacky:payablegolbez` | *none* — baked into the build |
| Objective | `0x32 boss_golbez` — "Defeat Golbez" | `0x13 char_golbez` — "Get Golbez" |

Orthogonal and complementary. But they share the word "Golbez" in code, flags and
UI, which is where the care is needed.

### 5.1 Collision points to handle

| # | Collision | Detail |
|---|---|---|
| 1 | **Module name** | 4.7.0 already owns `golbez_rando.py` for the boss; the fork correctly keeps `fusoya_rando.py`, so **do not** add a second `golbez_rando.py` |
| 2 | **Objective slugs** | `char_golbez` (`0x13`) sits beside `boss_golbez` (`0x32`) — the UI must disambiguate ("Get Golbez" vs "Defeat Golbez") |
| 3 | **Objective pools ×8** | 4.7.0 lists `char_fusoya` in **all eight** `O1:…`–`O8:…` pools |
| 4 | **`C`-namespace flags** | `Conly:`, `Cno:`, `Cstart:`, `Cvanilla`, `-vanilla:fusoya` … |
| 5 | **A whole `FUSOYA` section** | 4.7.0 added one 4.6.0 lacked (§8) |
| 6 | **Boss flags** | `Bwhybez`, `Bwhichbez`, `-wacky:payablegolbez` are boss behaviour — leave alone; a playable flag needs its own name |
| 7 | **`sprite_rando.py`** | The fork's NPC sprite swap must be re-applied against 4.7.0's differing table |

## 6. Integration model — two engines, chosen at launch

```
            ┌─────────────── launcher: choose engine ───────────────┐
            │                                                      │
   vanilla engine (4.7.0.Gale)                    Golbez engine (4.6.0.open fork)
   ├─ assets/python_ext/                          ├─ assets/python_ext_golbez/
   ├─ assets/spec/ui_spec.json (full)             ├─ assets/spec_golbez/ui_spec_golbez.json (trimmed)
   └─ updatable from galeswift git                └─ includes Golbez.ips / Map / Portrait + mirror
```

What "work like our engine" requires:

1. **Vendor the tree** as a second engine directory (`FreeEnt` + `f4c`; share `pyaes`).
2. **Ship the three `.ips` at the engine root** — `apply_ips_patch` looks in
   `root_dir` then falls back to a relative name — **and make a miss a hard error** (§4.2).
3. **Generalise the plumbing**: `SeedEngine` already takes an engine directory and
   `fe_bridge.set_ext_path(path)` exists, so passing a mode through is contained work.
4. **Per-engine extraction stamp and per-engine spec** (the 4.6.0.open flag
   vocabulary differs), so updating one engine doesn't disturb the other.
5. **Mode selected at launch and stamped into session metadata**, so *Play*,
   *Regenerate* and *New seed with these flags* use the right engine and a Golbez
   ROM can never be confused with a vanilla one.
6. **Emulator, saves, save states and the checks tracker need no changes** — they
   are engine-agnostic (same FF4 base, same WRAM layout, same `$12A0` switches).

### 6.1 Costs

| Item | Detail |
|---|---|
| APK size | **+~20 MB** if bundled, or ship the Golbez engine as a downloadable bundle (pairs well with engine-only updates) |
| Feature drift | The Golbez engine is frozen at 4.6.0.open: no `Tmintier`, new chest modes, WACKY/HARP/ZEROMUS/AGILITY/EXPERIENCE/FUSOYA or doors — until rebased |
| Specs | Two specs and possibly two preset sets to maintain |
| Legal | Nicoc1991's sprite/portrait art needs permission and credit; `THIRD_PARTY_NOTICES.md` updated |
| Hygiene | Delete `FreeEnt/ff2.smc`; `git init` the fork before vendoring |

## 8. Trimming the Golbez engine's scope

Removing FuSoYa invalidates a large slice of the flag surface, so the Golbez
engine's spec should be **smaller than vanilla's**. Measured from the 4.7.0 spec:

| FuSoYa surface in 4.7.0 | Size |
|---|---|
| **`FUSOYA` section** (its own menu section) | 3 top-level controls; 5 challenge modes (`Fweighted`, `Fsequential:p`, `Fsequential:r`, `Flocation`, `Fnerfed`, `Fvanilla`) plus `Fslowstart`, `Funlearn`, `Funcapped`, `Frandomhp` — **~20 controls** |
| `char_fusoya` in the objective pools | **8 occurrences** (`O1`–`O8`) |
| `fusoya` mentions in `ui_spec.json` | **98** |
| Engine side | `fusoya_rando.py`, `WHITE_MAGES`, dialogue names, custom-weapon `_EQUIP` lists |

Suggested trim for `ui_spec_golbez.json`:

1. **Drop the `FUSOYA` section** (replace with a small GOLBEZ section if spell-learning
   options are wanted). This removes the entire `F*` namespace, freeing it for a
   compact Golbez set.
2. **Rename** the 8 pool entries `char_fusoya` → `char_golbez`.
3. **Drop or rename** the `C`-namespace FuSoYa options (`Conly:`, `Cno:`, `Cstart:`,
   `-vanilla:fusoya`).
4. Ship it as its own JSON — our per-mode spec loading already handles this.

Result: a smaller, clearer menu than vanilla's, and less surface to keep in sync.

## 9. Bottom line

- **Technically proven.** The sprite replacement reproduces byte-for-byte on a
  4.7.0 ROM (9/9 regions), the sprite space is free under every flagset tested,
  and nothing the randomizer touches overlaps the patched tables.
- **Two engines is a sound choice**, and it lets the vanilla engine keep taking
  upstream updates while the Golbez engine stays frozen at its own base.
- **Two bugs to fix first**: the ineffective portrait mirror (likely the cause of
  the unresolved "renders FuSoYa" blocker) and the silent patch-skip.
- **The scope trim is largely free work**, since most of FuSoYa's flag surface
  disappears anyway.
